# Бронирование переговорной

Vue 3 + TypeScript. Одна комната, календарь дня, рабочие часы 09:00–18:00. Время комнаты — Asia/Bishkek (UTC+6).

## Запуск

Node.js 22.12+ и npm:

```sh
npm ci
npm run dev
```

Открыть адрес Vite, обычно http://127.0.0.1:5173.

```sh
npm test          # Правила, mock API, Pinia
npm run build    # TypeScript и сборка
npm run preview  # Просмотр сборки
npm run test:e2e # Desktop/mobile в Google Chrome
```

Для E2E нужен установленный Google Chrome. Другой вариант: установить Chromium через `npx playwright install chromium` и убрать `channel: 'chrome'` из playwright.config.ts.

## Что сделано

- Выбор дня, месячный календарь, расписание, создание, редактирование и удаление с подтверждением.
- Собственные поля даты и времени. Любые минуты доступны через текстовый ввод; меню предлагает шаг 15 минут. Стрелки ↑/↓ меняют минуту, Shift+↑/↓ — 15 минут.
- vee-validate + Zod: рабочие часы, `start < end`, 30–120 минут, запрет прошедшего времени и пересечений. Соседние брони разрешены, текущая бронь исключается при редактировании.
- Загрузка, пустое расписание, ошибки списка и формы, блокировка повторной отправки. После 409 список обновляется, черновик остаётся в форме.
- Pinia для выбранной даты и списка. Отмена предыдущего GET при смене даты.
- Адаптивность, клавиатура, доступные названия и возврат фокуса. Reka UI используется напрямую для поведения диалогов и popover.
- Авторские стили на SCSS: отдельные файлы компонентов, общие токены и миксины. Tailwind подключён отдельно для reset и служебных классов. IBM Plex и Remix Icons поставляются пакетами.

Референсы интерфейса: [Cal.com](https://starter.cal.com/book/rickastley/30min), [Skedda](https://www.skedda.com/platform/meeting-room-booking-system).

## Mock API и service worker

Компоненты обращаются к src/api/bookings.ts, который выполняет обычный fetch:

```text
GET    /api/bookings?date=YYYY-MM-DD
POST   /api/bookings
PATCH  /api/bookings/:id
DELETE /api/bookings/:id
```

MSW перехватывает запросы через public/mockServiceWorker.js; ответы формируют src/mocks/handlers.ts. Обработчики повторно проверяют правила и возвращают 409 при пересечении. Это mock API в браузере, отдельного сервера и БД нет. Записи сохраняются в localStorage; при его недоступности — в памяти текущей вкладки.

Worker нужен выбранному способу имитации API. Он сгенерирован библиотекой, не добавляет PWA, офлайн-кеш или push-уведомления. Не редактировать вручную. В статическом демо MSW запускается и в production. Для реального API убрать его запуск из main.ts и настроить адрес запросов в api/bookings.ts.

## Проверка серверных ошибок

На /?demo=1 есть панель «Демо», в обычном интерфейсе она скрыта:

- «Конфликт при сохранении (409)» — следующая корректная отправка имитирует конкурирующую бронь. При редактировании имитируется внешнее изменение текущей записи.
- «Ошибка сохранения (503)» — следующая операция создания, изменения или удаления завершится ошибкой; повторная попытка работает.
- «Ошибка загрузки» — один GET завершится ошибкой; «Повторить» восстановит список.
- «Сбросить демо-данные» — восстановит три примерные встречи сегодня и завтра. Ограничения в три брони нет.

## Решения и ограничения

- Прошедшие дни доступны для просмотра. Начавшуюся бронь можно удалить, редактирование заблокировано — выбранная трактовка запрета бронирования прошлого времени.
- Линии расписания идут через 30 минут, но это не ограничение на начало: 10:07–10:37 тоже допустимо.
- Нет авторизации, повторяющихся встреч, drag-and-drop и реального совместного доступа. Вкладки не синхронизируют состояние; localStorage не заменяет общую БД. Имитация 409 при редактировании не является системой версий записей.
- После успешной записи календарь получает свежий список. Если обновление не удалось, операция уже сохранена: экран показывает ошибку загрузки и предлагает повторить GET.
- Supabase и реальный backend не подключены: для этого тестового достаточно mock API.
